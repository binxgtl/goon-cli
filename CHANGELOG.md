# Changelog

## Unreleased

### Dynamic workflow, scope loop & multi-candidates (v0.7, P22-P24)
- Added the pure dynamic workflow classifier `classifyWorkflowComplexity(prompt, context?)` in `src/workflow.ts` (no model call): counts distinct imperative verbs (English + common Vietnamese), strong sequencing connectors ("and then"/"then"/"sau đó"/"after that"/"tiếp theo" — regexes handle the ASCII-only `\b` limitation of JS for diacritic endings), path mentions plus an optional caller `fileCount`, and multi-step keywords. Conservative by design: with no strong signal the verdict is `single`, so ambiguous prompts never escalate (`single` reasons enumerate the observed signals). New step type `dag` for workflow definitions (JSON schema and the markdown `[dag]` heading attribute) executes the multi-agent DAG through the new `WorkflowExecutionHooks.runDag` **only** when the classifier returns `multi`, the caller sets `multiAgentEnabled` (`multiAgentMode !== 'off'`) and the hook exists — otherwise the step runs as a plain prompt, keeping legacy linear workflows byte-for-byte behavior (dag-free workflows are never classified). Each classified `dag` step emits the additive `workflow_classified { mode, reason }` event. The CLI `/dag` core (planner + `runDag` + fail-closed verification with the parent approval policy) was extracted into a shared `runDagCore` used by `/dag` and by the `dag` steps of `run_workflow`/`/workflow` (workflow budget pinned via `withBudget`).
- Added the scope loop `runScopeLoop(goal, hooks, opts)` in `src/coord.ts` (§8.2): attempt → `runVerification` → on fail **expand** the next attempt's context (redacted `formatVerifyErrors` output via `opts.secrets`, related files, display commands) and on pass **contract**; at most `min(verify.maxRepairRounds + 1, 4)` rounds (`scopeRoundCap`). Stops on pass, no tracked file changes, an exhausted shared `RunBudget` (`budgetStopReason` checks the token limit and the ledger's cost/time caps **before** every attempt), exhausted rounds or cancellation; a terminal failure rolls every accumulated snapshot back per §5.1 (restore without force, conflicts retained in the turn window). Verification is fail-closed: a plan with commands and no `opts.approve` throws `VerificationApprovalError` before anything runs; approval denial is a skip (pass) verdict with no rollback; AST-only plans run without approval. A failure mid-attempt drains the active snapshot window before the rollback, so a cancelled attempt never leaks partial writes. New additive `scope_round { round, action: 'expand'|'contract'|'stop', reason }` events.
- Added multi-candidate generation in `src/coord.ts` (§8.3): `candidateCap` (requested count clamped to `MAX_CANDIDATES = 2`), `reflect(candidate, verdict)` (warn/skip count as pass, matching §5.1), `rerank` (verify pass > fewer warnings > lower cost > lower generation index — deterministic), `costDegrade` (degrade when <20% of the cost or time budget remains) and the `runCandidates(task, hooks, opts)` runner. Candidates run sequentially on the shared `WorkspaceFiles`: each is isolated with `beginTurn`/`takeTurnBackups`, verified, and rolled back immediately on failure (a mid-`generate` failure drains the active window first), so a losing attempt never leaks into the next attempt; the first non-failing candidate is kept on disk and its snapshot merged back into the turn window for checkpointing. Under budget pressure the runner degrades to a single candidate and asks the `generate` hook for reduced effort via `degraded: true`, emitting the additive `cost_degrade { reason, candidates }` event. A hard token-budget stop before any candidate yields `ok: false` with the cap reason.
- Added `src/embedder.ts` (P24 real embedder seam): `createEmbedder({ provider, model, baseUrl, apiKey, fetchImpl, timeoutMs, batchSize })` with `hash` (default; returns the unchanged deterministic `HashEmbedder`), `openai` (`POST {base}/embeddings`, bearer token only in the `Authorization` header, batched at 64 texts/request, vectors mapped by response `index`) and `ollama` (`POST {base}/api/embed`, default `http://127.0.0.1:11434`, never receives the key). Errors never leak the credential: status plus an apiKey-scrubbed body snippet (≤200 chars). The CLI passes the factory result into `MemoryStore.open` when `embedderProvider !== 'hash'`; a misconfigured remote embedder degrades to the hash embedder with a stderr note instead of disabling memory, and embedder failures stay `memory_error` (never a failed run). Config (all defaulted, `.strict()` schema keeps old configs parsing): `embedderProvider='hash'`, `embedderModel?`, `embedderBaseUrl?`; env `GOON_EMBEDDER_PROVIDER`, `GOON_EMBEDDER_MODEL`, `GOON_EMBEDDER_BASE_URL`.
- `HarnessEvent` gained the additive variants `workflow_classified`, `scope_round` and `cost_degrade` (typed via `WorkflowEvent`/`ScopeEvent`/`CandidateEvent`); plain renderer, TUI and event log handle them (JSON mode prints any event type; unknown types stay ignored by old consumers).
- Tests: 13 `tests/workflow-classifier.test.mjs` (single/multi signal table, conservative ambiguous defaults, connector/keyword/path/fileCount rules, `dag` step gating matrix including `multiAgentEnabled=false` and missing hook, legacy linear workflows never classified, markdown `[dag]` parsing + details rendering), 12 `tests/scope-loop.test.mjs` (`scopeRoundCap`, fail×2→pass with exact-command approvals, secret redaction in expanded output, fail-closed rejection with rollback, denial-as-skip, AST-only without approval, pre-attempt and mid-loop budget stops, exhausted-rounds rollback, no-change stop, cancellation rollback, `budgetStopReason` caps) and 9 `tests/reflection.test.mjs` (cap clamp, reflect verdict mapping, rerank order + deterministic ties, cost/time degrade threshold, candidate-1-fails→candidate-2-wins with rollback, all-fail rollback, degrade to one candidate with event, hard budget stop, throwing-hook rollback) plus 7 `tests/embedder.test.mjs` (hash default byte-identical, openai batching/bearer/index-mapping, ollama keyless request, key-leak redaction on HTTP/network/non-JSON failures, fail-closed factory, config defaults + env precedence).

### Multi-agent DAG (v0.6, P20-P21)
- Added `src/coord.ts` (no model calls, no shell of its own): `validatePlan` (unique non-empty ids, existing `dependsOn`, no self-deps, acyclic via Kahn, valid roles → `PlanValidationError`), `planFromPlanner` + `plannerPlanSchema` (zod), `Scheduler` (`depsMet` only when every dependency is `done`; a `failed`/`blocked` dependency blocks dependents transitively; `dispatchReady` respects write-serial (`coder` one at a time) and read-parallel bounds; deadlock detection with pending todos marked `blocked` → `PlanDeadlockError`), `applyReviewVerdict` (rework counter, cap default 3 → `failed`), and `merge` (validate/aggregate only — never applies: conflicts when two done todos changed the same file with non-empty diffs; empty combined diff without artifacts → `verified: false` "no changes" unless `allowEmpty`; optional verifier → `verified: false`).
- Added `runDag(goal, hooks, opts)`: planner → validate → scheduler (write roles serial) → spawn via the caller's hook (the CLI wires it to the public `Subagents.runTasks`) → optional review/test with per-todo `WorkspaceFiles.beginTurn()` snapshot and rollback-then-rework (a restore that would clobber newer user edits fails the todo instead) → mark done → merge → final verify. Verify failure, merge conflict, "no changes", plan failure and cancellation all roll back every per-todo backup in reverse order before throwing (`ErrNotVerified` / plan-failed error). Every spawn receives the same shared `RunBudget`; when none is passed a fallback budget is seeded from `runTokenBudget` (else 200 000 tokens) and config cost/time caps. `ROLE_TOOLSETS` pins per-role tools (`planner`/`reviewer`/`researcher` read-only; `coder` adds `write_file`/`edit_file`/`apply_patch`/`bash`; `tester` adds `bash`); MCP tools are excluded unless the caller opts in via `multiAgentMcpTools`/`allowedMcpTools`.
- `ToolRegistry` gained an optional fourth constructor argument `allowedTools` (exact names or trailing-`*` wildcards such as `mcp__*`): `schemas()` omits non-allowed tools and `execute()` rejects them even when the model names a hidden tool directly. `Subagents` gained a public `runTasks(tasks, { readOnly, signal, budget?, allowedTools?, role? })`; `delegate_task`/`delegate_edit` and `runDag` spawn through it and pin the parent's exposed toolset by default — model-supplied `allowedTools` never reaches it (the delegate schemas expose `tasks` only, and the child registry is pinned regardless), so a delegated or DAG child cannot self-escalate. `AgentRoleType`/`buildRolePrompt` cover the new DAG roles (prompts keep the "You are a delegated agent." prefix).
- CLI: `/dag <goal>` (interactive) and `goon dag <goal>` (positional, like `goon network <topic>`) run the full lifecycle with an LLM planner (JSON plan, validated), shared budget seeded from the parent session/ledger (never a child counter), per-todo test and final verification through `runVerification` with the exact commands offered to the parent approval policy (fail-closed `VerificationApprovalError` when a hook has commands but no way to approve; verdicts redacted before events). `multiAgentMode: "off"` refuses `/dag`; read-only/plan mode refuses it too. New additive events `dag_plan_invalid`, `dag_plan_ready`, `dag_todo_update`, `dag_merge` rendered in the plain renderer, TUI and pair view; help updated.
- Config (all defaulted, backward compatible): `multiAgentMode='manual'`, `multiAgentReworkCap=3`, `multiAgentMaxConcurrency=2`, `multiAgentMcpTools=[]`.
- Review fixes: `runDag` only drains the shared `WorkspaceFiles` turn snapshot for **write** roles (a read-only todo completing mid-spawn can no longer steal a parallel coder's per-todo backups, misattribute diffs/artifacts, skip its test hook or fabricate merge conflicts); the shared `/dag` budget now inherits `config.maxCostUsd`/`maxTimeMs`/`startedAt` through `??=` even when the caller passes a bare budget object (cost/time caps are enforced in child harnesses again); `runTodo` funnels every spawn/review/test-hook failure through `failTodo` with a redacted bounded reason (surfaced in the `dag_todo_update failed` event, the todo report and the `Plan failed: t1(failed: <reason>)` detail instead of being swallowed), and `runDag` owns an internal abort controller linked to the caller's signal — on any failure it aborts remaining spawns, drains all sibling promises with `Promise.allSettled` before rolling back (no child keeps writing after the rollback, no unhandled sibling rejections).
- Known issue 7 (package-manager scripts in auto mode — accepted product decision): `npm test`/`npm run build`/`npm run lint`/`make test` stay **low** (auto-approved) because auto mode already auto-approves `node <script>` (medium) and a package lifecycle script is the same trust domain; the red-team tests now pin every escalation variant as NOT low — unknown/lifecycle scripts (`npm run pretest`/`posttest`/`deploy` → medium), flag-redirected invocations (`npm --prefix <dir> test`, `yarn --cwd <dir> test` → medium), arbitrary execution (`npm exec`/`npx`/`pnpx` → high), and any compound with a network segment (→ high, never auto-approved or remembered). Decision recorded in README (Bảo mật) and `tests/risk.test.mjs`.
- Tests: 14 `tests/coord.test.mjs` (plan validation matrix, scheduler blocked/serial/parallel/deadlock, rework cap, merge conflicts/empty/verify, diff path parsing, role toolsets, validate-failure never spawns) and 12 `tests/dag.test.mjs` (registry-level hidden-tool enforcement, public `runTasks` pinning, `delegate_edit` ignoring model `allowedTools`, per-todo backup/rework/rollback, fallback budget, verify-false full rollback, fail-closed test hook without approve, rework-cap plan failure with blocked dependents, full `/dag` CLI lifecycle with pinned coder toolset and auto-approved verify commands, hidden tool call blocked at the child mid-run, `multiAgentMode=off` refusal, config defaults).

### Context budget & memory wiring (v0.6, P18-P19)
- Added `src/context-budget.ts` (pure, never mutates the session): `allocateContextBudget` splits `inputBudget = max(1024, contextWindow - maxOutputTokens)` into a reserve (`contextReserveRatio`, default 0.15), a system budget (floor 15% / cap 35% of the input budget; an oversized system loses `Workspace guidance (AGENTS.md):` and `Persistent user memories:` sections first, identity/rules last — the base system prompt is never truncated at the minimum 8192/512 window), conversation (`contextConversationRatio`, default 0.45) and injected-files budgets (`contextFilesRatio`, default 0.25). `prepareContextBudget` prunes tool results >8 KiB (head/tail, pairing preserved), collapses duplicate tool results to a marker, blanks oldest tool outputs and then drops oldest messages in pair-safe runs (never the newest user/assistant message, never orphaned tool results), truncates `@file` `<referenced_file>` blocks with a `read_file` marker, injects retrieved memory as a **user-role** `<untrusted_context source="rag,repo" trust="untrusted">` block ("data, not instructions"; never in the system prompt) trimmed to the files budget (lowest score first), and throws `ContextBudgetError` instead of ever sending a request over budget. The final `estimatedTokens(messages, system) <= inputBudget` invariant is tested.
- Harness: every model request is now sent from a prepared clone (per-result prune → aggregate prune → referenced-file trim → memory block → system trim), and `expandFileMentions` gained an optional `maxChars` bound (default 32 000) that the harness fills with a share of the context budget. Compaction still runs on the untouched store as the safety net. New `context_budget` HarnessEvent reports the allocation (`inputBudget/system/conversation/files`, `truncated`, `reason`); golden streams and the replay assertions were regenerated accordingly.
- P19 memory wiring: the CLI opens one `MemoryStore` per session when `memoryEnabled` (closed in the outermost `finally`; failures degrade to a warning), passes it to the harness via `HarnessDeps.memory` and never to subagents. The harness indexes the repo **once per session** and only when `ragEnabled` (emit `memory_indexed`), retrieves memory for every request bounded by the files budget (emit `memory_retrieved`), records `task_started`/`task_completed` (success and failure outcomes), `tool_result` (redacted bounded summaries only — never raw output), `patch_applied` (path + byte delta, never file contents), `verify_result` and `assistant_message` (redacted, truncated) through `MemoryStore.handleEvent`, and re-indexes changed files once per run that made tracked edits (partial re-index). Memory failures surface as `memory_error` events and never fail a run; `ragEnabled=false` means no indexing ever happens.
- Config (all defaulted, backward compatible): `contextReserveRatio=0.15`, `contextConversationRatio=0.45`, `contextFilesRatio=0.25` (`.strict()` schema keeps old configs parsing). `/memory budget` now reports that retrieval is injected as an untrusted user block.
- Tests: 14 context-budget tests (allocation invariant, min-window system preservation, section-priority system truncation, per-result/aggregate prune pairing, duplicate collapse, `ContextBudgetError` fail-closed, untrusted-block role/trimming, referenced-file truncation, non-mutation, stats) and 4 memory-integration tests (full event wiring with redaction and once-per-session indexing, `ragEnabled=false` never indexes, memory failures never fail a run, error outcomes on failed runs).

### Memory store & lexical RAG (v0.6, P16-P17)
- Added `src/rag.ts`: lexical RAG ("hashed term-frequency", deliberately **not** semantic). Deterministic FNV-1a `HashEmbedder` (384 dims, offline), `Embedder` seam for a future real embedder, `chunkFile` (per-function/class TS/JS/Go/Python via regex with a 40-line/8-overlap fallback window; soft 1500 / hard 4000 chars), in-memory `LexicalIndex` (linear-scan cosine, top-k with deterministic tie-breaking, threshold, LRU eviction by `lastAccess`, capacity 5000 default), `.goonignore` subset parser (comments, blanks, `!negation`, trailing `/` dir-only, `*`, `?`, `**/`), and `indexRepo`/`walkRepo` which skip symlinks, real paths outside the workspace root, oversized (>1 MiB) or binary files, sensitive paths (`.env*`, `*.pem`, `*.key`, `id_rsa*`, `.npmrc`, `.ssh/**`, `.aws/**`, `secrets/**`, gcloud credentials, …), default cold-start dirs (`.git`, `node_modules`, `vendor`, `dist`, …) and `.goonignore` rules. Chunk contents pass `redactSecrets` before anything is stored. Persistence: per-project `rag.json` (`{version, cwd, indexedAt, files:{path:{mtimeMs,size,chunks}}}`) with vectors recomputed on load; `ensureRepoIndexed` re-indexes only files whose mtime/size changed and dedups in-flight calls.
- Added `src/memory.ts` (`MemoryStore`): six kinds — `working` (per-turn RAM), `conversation` (live view over session messages, never re-retrieved), `exec` (rolling 50 compact per-project lessons), `repo` (cached repo-tree summary, invalidated on patches), `knowledge` (lexical index + insights), `preference` (per-user key/value `preferences.json`, separate from `memories.json`). `handleEvent` is the single write entry point (`task_started|state_changed|task_completed|assistant_message|tool_result|patch_applied|verify_result|user_preference`); all writes serialize through one promise chain with atomic file writes, so concurrent `handleEvent`/`persist` calls never corrupt state, and every persisted string is redacted first — `MemoryStore.open` always merges `collectSecrets()` (credential-looking env vars like `*_API_KEY|*_TOKEN|*_SECRET|*_PASSWORD`) into its redaction list alongside any explicit secrets, the same contract as the event log, so a bare env credential inside an indexed file can never reach `rag.json`/`memory.json`. `retrieve(query, budgetTokens)` returns working notes, repo tree, budgeted lexical chunks and query-relevant preferences — never conversation/exec raw.
- CLI: `/memory rag index|stats|search`, `/memory budget`, `/memory pref set|get|rm|list` (store opened on demand, always closed; failures reported, never fatal). `/memories list|add|rm|clear` (and `/memory <text>`) unchanged. `/memory` added to the TUI command list, descriptions and help.
- Config (all defaulted, opt-in): `memoryEnabled=false`, `ragEnabled=false`, `ragTopK=10`, `ragCapacity=5000`, `ragThreshold=0`, `ragIndexMaxFiles=2000`, `ragIndexMaxFileBytes=1048576`; env `GOON_MEMORY_ENABLED`, `GOON_RAG_ENABLED`, `GOON_RAG_TOP_K`, `GOON_RAG_CAPACITY`. Memory data lives in `<data>/memory/<projectId>/` with `projectId = sha256(cwd)[0..16]`.
- `src/redact.ts`: `.config/gcloud/**` credentials added to `isSensitivePath` (keeping the existing conservative `.env*` behavior, which also covers `.env.example`).
- Tests: 15 RAG tests (FNV/embedding determinism, chunking windows and caps, goonignore matrix, symlink/outside-root skip, sensitive/binary/oversize skip, redaction, snapshot round-trip, top-k ties, LRU eviction, threshold, file-cap truncation) and 13 memory tests (six kinds, event routing, single-writer concurrency, exec rolling limit, preference file separation, persisted redaction, retrieve content/budget, idempotent/staleness/in-flight indexing, insight restart, redaction patterns, config defaults, TUI registration, corrupt-file recovery).

### Shared budgets and cross-platform CI (v0.5, P14-P15)
- Subagents, Codex-style spawned agents, Agent Network personas and workflow prompt steps now share the parent `RunBudget` (token/cost/time caps) and `CostLedger`. Child registries inherit the parent `ExecutionPolicy`, so network deny/allowlist gates and process limits apply inside children (and are enforced before approval). Child harnesses never overwrite the budget's cost mirror with their own fresh session counter; costs are aggregated from each child session delta.
- Agent Network copies `parentBudget.costSpent` back after every persona and the synthesis, so `/cost`, `/status` and the shared budget mirror see the full run.
- Delegation stays pinned: `delegate_task`/`delegate_edit` accept only tasks; model-supplied `allowedTools` is stripped by the schema and children always inherit the parent-mode toolset (no self-escalation to bash/MCP/delegation).
- Workflow steps share one budget in both `run_workflow` and `/workflow` (including `subagent`/`network` steps) instead of starting a fresh budget per step.
- CI now runs a 3 OS × 2 Node matrix (`ubuntu-latest`, `windows-latest`, `macos-latest` × Node 22.16/24) with `fail-fast: false`; POSIX mode/umask tests and the POSIX `gh` shim test skip on Windows. The test script quotes the glob so Node expands it on every shell, and runs with `--test-concurrency=4`: each test file is its own Node process, and letting 7-8 run at once on Windows can exhaust the system commit charge (`FATAL ERROR: Committing semi space failed`), which silently truncates the remaining tests of the killed file. Added `.gitattributes` (LF normalization + binary excludes) and `scripts/smoke-termux.sh` for manual Termux validation.
- Tests: child policy denial before approval, shared ledger/cost mirror across overlapping children, ignored `allowedTools`, network budget sync, and a workflow token-budget integration test.

### Risk and cost ledger (v0.4)
- Added `src/risk.ts` with `RiskClass` (low/medium/high/critical), quote-aware shell segmentation, wrapper peeling, package-manager and git classification, plus MCP risk assessment. Critical commands are denied before approval; high commands never auto-run or enter the session allowlist; exact/prefix bash allowlists only medium/low. Three identical denials stop the run.

### Patch safety

Added public `peekTurnBackups`, `turnChangedFiles`, `hasTurnChanges`, `clearTurnBackups` and `replaceTurnBackups` APIs on `WorkspaceFiles`.

### Verification hook (v0.4, P06)
- After every batch that wrote workspace files, `Harness` runs the verify plan (syntax first, then configured/auto-detected test/lint/typecheck commands). Failures are injected into the next turn (redacted), with `maxRepairRounds` (default 2) repair attempts.
- Exhausting repairs, or ending the turn with an unresolved failure, rolls the turn back byte-exactly (new files deleted, previous content/mode restored) and ends the run with exit code `1`. Files the user changed after the agent are kept as conflicts and stay restorable via `/revert`.
- New events: `verify_start` (`files`, `commands`), `verify_result` (`status`, `stage?`, `reason`, `errors`, `warnings`, `durationMs`), `verify_rollback` (`reason`, `restored`, `deleted`, `conflicts`). Approval denials clear the verdict and attempt counter without rolling back.
- Redaction (`redactVerdict`/`redactText`) runs before any verdict reaches an event or the session file. Subagent, workflow-step and network-agent child harnesses always run with verification disabled.

### Verify flags, cost caps and docs (v0.4, P07-P08)

- Config: nested `verify` block plus `GOON_VERIFY_*` env vars, merged per key so flags/env never drop policy defaults.
- README documents the hook, limits (workspace edit tools only; bash/MCP writes are not tracked), and the auto-mode package-script behavior. Integration tests cover fail→repair→pass, rollback on give-up, approval skip, disabled child harnesses, redaction, config precedence, and the package-manager red-team case.

  trạng thái (chế độ, model, effort … workspace (nhánh), todo, ctx %, token). Một màu nhấn duy nhất;
  màu khác chỉ xuất hiện khi mang trạng thái (diff, lỗi, duyệt quyền, auto-approve).
- Banner, `/btw`, `/recap`, resume và `goon setup` là các khối chữ ngắn, tự xuống dòng ở mọi độ rộng.
- `/resume` có 2 tab **This folder** / **All projects** (←→ hoặc Tab đổi tab, gõ để lọc); resume
  phiên của dự án khác tự chuyển workspace. `goon resume` / `goon --resume ID` chạy được từ mọi thư mục.

### Bảo mật
- Chuyển từ `auto`/`--yes` về `ask`/`plan` bật lại việc duyệt quyền ngay lập tức.
- Shift+Tab khi đang có prompt duyệt chỉ duyệt một lần, không còn cấp "always".
- API key của goon không còn lọt vào môi trường của `bash`, `!cmd`, `rg`, `git`.
- Đọc ảnh do model yêu cầu ngoài workspace cần duyệt; tool bị ẩn không gọi được bằng tên.
- Nhập API key ẩn; cảnh báo base URL `http://` không phải loopback; không xoá phiên mơ hồ/đang mở.
- Nâng AI SDK, `ajv`, `zod`: `npm audit` 0 lỗ hổng.

### Sửa lỗi
- `edit_file` không còn làm hỏng nội dung chứa `$&`, `$'`, `` $` ``, `$$`.
- Ảnh đính kèm không còn làm vượt context hay khiến phiên không resume được (phiên cũ tự được sửa).
- `apply_patch` hỗ trợ `Move to`, nhiều khối cho một file, newline cuối file.
- `/revert` không ghi đè file bạn sửa sau lượt của agent (`--force` để ghi đè).
- `/effort` có hiệu lực ngay; đổi effort khi đang chạy không còn giết MCP/subagent của lượt đó.
- `!cmd` và `/goal` khi đang chạy không còn làm hỏng thứ tự lịch sử (lỗi 400 từ provider).
- Lệnh gõ khi đang bận được xếp hàng thật; wizard luôn cho đổi model.

### Hiệu năng
- Render TUI tăng dần (~80 lần nhanh hơn mỗi frame), `--version`/`--help` ~5 lần nhanh hơn,
  liệt kê phiên có chỉ mục, MCP khởi động song song và được tái sử dụng, 6 tool đọc chạy song song,
  retry tôn trọng `Retry-After`.

### Tiện ích cho dev
- `git diff | goon -p "review"`, `goon -p ... < file`, `-o/--output-last-message`.
- Duyệt theo tiền tố lệnh (`p`), prompt tuỳ biến `/prompts:<tên>`, `/key`, `/provider`,
  chuông báo khi cần chú ý (`GOON_NOTIFY=0` để tắt), clipboard cho Termux/Wayland/xsel.
